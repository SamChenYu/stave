stave

A music notation renderer for the terminal.

C++20 CMake 3.20+ MusicXML · MEI · ABC · SVG sixel · kitty · braille MIT
Build it Quick start View source

stave opens a MusicXML, MEI or ABC score and lets you page through it in the terminal, bar by bar and staff by staff. Text characters are too coarse for engraved notation, so stave draws the score as real pixels. It can also colour bars and single notes green, yellow and red to show what changed between two versions of a score. That is how motif shows its diffs.

How it works#

Score.musicxml .mxl .mei .abc
→
Verovioengraves one long system as SVG
→
lunasvgrasterises the SVG to pixels
→
Terminalsixel, kitty or braille

Verovio lays the score out as a single system with no line or page breaks, so it scrolls sideways. stave reads where each bar and staff sits in that SVG and moves through the score one bar or one staff at a time. You can also give it any plain SVG, and it pans and zooms across the drawing instead.

Build#

You need CMake 3.20 or newer, Git, and a C++20 compiler: MSVC 2022, GCC 11+ or Clang 14+. Verovio, lunasvg and doctest come in as Git submodules.

shell
$ git clone https://github.com/SamChenYu/stave
$ cd stave
$ git submodule update --init
$ cmake -S . -B build
$ cmake --build build --config Release

stave looks for Verovio's music fonts in a verovio-data folder next to the executable. If you move the binary somewhere else, take that folder with it, or point at it with --verovio-data DIR.

Quick start#

Open one of the bundled example scores full screen:

shell
$ stave examples/beethoven-op18no1-mvt1.mxl

A few more things to try:

shell
$ stave --test-pattern                  # can this terminal show images?
$ stave FILE --bar 9 --staff 2          # start at bar 9, second staff
$ stave FILE --paper                    # dark ink on a cream page
$ stave FILE --print                    # print inline, like cat
$ stave FILE --png out.png              # save the first screen as a PNG
$ stave FILE --added 40-60 --removed 7  # colour bars to show a diff

Options#

usage
stave FILE [options]
stave --compare OLD NEW [options]
stave --test-pattern
stave --terminal-info

FILE is a score (MusicXML .musicxml, .xml or compressed .mxl, MEI .mei, or ABC .abc) or an SVG.

OptionWhat it does
Opening a file
--svg FILETreat FILE as an SVG, whatever its extension.
--bar NStart at this bar, by its printed number. A pickup is usually bar 0.
--staff NStart at this staff, counting from 1 at the top.
--width NHow wide to draw it at first, in pixels.
--verovio-data DIRWhere Verovio's music fonts are. Defaults to verovio-data next to the executable.
Showing a diff
--added BARSDraw these bars in green. See marking bars.
--changed BARSDraw these bars in yellow.
--removed BARSDraw these bars in red.
--marks FILE.jsonMark bars or single notes from a JSON file. See marking notes.
--name NAMEWhat the status line calls the file (default: its file name), such as "song @ HEAD~1".
--summary TEXTA line of text shown above the status line, such as what a diff changed.
Side by side
--compare OLD NEWShow two versions side by side, old on the left, scrolling together. See side by side.
--before-marks FILE.jsonMarks for the old version, in the same format as --marks.
--before-name NAMEWhat the status line calls the old version.
--pairs RUNSWhich bars of the old version match which bars of the new, as OLD=NEW runs.
Output
--sixel, --kitty, --brailleForce one way of drawing. By default stave uses the best one the terminal supports.
--paperDark ink on a cream page, instead of the terminal's own colours.
--printPrint it inline at the terminal's width, like cat. This always happens when output isn't a terminal.
--png OUT.pngSave the first screen as a 1600×900 PNG, dark ink on a cream page, instead of showing it.
Diagnostics
--test-patternDraw a test image, to check that the terminal can show graphics.
--terminal-infoShow what stave found out about this terminal.
--benchTime loading the file, drawing a screen, and each output method.
--versionPrint the versions of stave, lunasvg and Verovio.
STAVE_DUMP_SVG=FILEEnvironment variable. Saves the SVG that Verovio draws for a score, for debugging.

Terminals#

stave checks what the terminal can do when it starts, and picks the best output it finds. Run stave --terminal-info to see what it detected.

Sixel default

Real pixels. Windows Terminal 1.22+, WezTerm, foot, iTerm2.

Kitty opt-in

kitty, Ghostty, WezTerm. It works, but it flickers, so stave only uses it when you pass --kitty.

Braille fallback

Any terminal. Each character cell shows 2×4 dots. It's coarse, but it works everywhere.

Marking bars#

--added, --changed and --removed colour whole bars green, yellow and red.

shell
$ stave new.musicxml --added 40-60 --changed 12-15@2,20@3 --removed 7
ValueMarks
7bar 7
12-15bars 12 to 15
12-15@2bars 12 to 15, only on staff 2
3,7-9@1,20any mix of those, separated by commas

Bars go by their printed numbers, so a pickup is usually bar 0. Staves count from the top, starting at 1. Press n and N to jump between changes.

Marking notes#

A diff usually changes a few notes rather than whole bars. --marks takes a JSON file with a list of marks, and each mark can pick out single notes:

diff.json
[
  {"tone": "changed", "bar": 12, "staff": 2, "at": "3/2", "pitch": 66},
  {"tone": "added", "bar": 14, "to": 16}
]
FieldMeans
toneadded, changed or removed
barThe bar's printed number.
toThe last bar, to mark a run of whole bars.
staffOnly this staff.
atOnly the notes starting here, in quarter notes from the barline: 2, 1.5 or "1/3".
pitchOnly the notes sounding this MIDI pitch, with transposing instruments taken into account.
voiceOnly the notes in this voice.
filltrue tints the bars' background in the tone instead of colouring their ink, like a diff's line highlight. Notes marked in the same bars still show their own colour on top.
  • A mark with at, pitch or voice marks notes. Without them it marks whole bars.
  • If every note of a chord gets the same mark, its stem and dots are coloured too.
  • A mark that matches no note is an error, and so is a note marked two different ways.

Side by side#

--compare shows two versions of a score next to each other, the old on the left and the new on the right. The keys move the new version, and the old one follows to the same bar and staff.

shell
$ stave --compare old.musicxml new.musicxml \
    --before-marks old.json --marks new.json \
    --pairs 1-17=1-17,19-40=18-39
  • --marks, --added and the like mark the new version. --before-marks marks the old one, so removed notes can be shown in red where they used to be.
  • --pairs says which bars of the old version match which bars of the new, as runs of OLD=NEW. In the example, old bar 18 was deleted. Without --pairs, bars are matched in order.
  • --name and --before-name label each side on the status line.
  • --bar and --staff set where the new version starts.
  • n and N jump between changes on either side.

Compare mode needs an interactive terminal, or --png to save the first screen. It only takes scores, not SVGs, and --print, --width and --bench don't work with it.

Tests#

shell
$ ctest --test-dir build -C Release --output-on-failure
